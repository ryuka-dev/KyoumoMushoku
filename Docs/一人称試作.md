# 一人称試作 ― ゴミ箱を叩く（灰箱）

制定日：2026-10-26
位置づけ：`作業計画.md` 第一の二節 K2。**2 日で区切る試作**であって、本編の作り直しではない。

---

## 〇、この試作が答える問い

**「漁る」は、手で遊んで気持ちいい動詞になるか。そして一人称はそれを横スクロールより強くするか。**

M1 の実測（`作業計画.md` 第八節）で、漁りは全行動 57 のうち 30（53%）を占めた。最も多く繰り返す動作の手応えが、
長押しの進捗バーしかない。第九節の命題②「ゴミ箱漁りに十分な手応えがあるか」は、実は立っていない。

ここを直すのが、審査員が最初の数分で触る体験を直すことになる。

## 一、範囲（厳密に守る）

| 作る | 作らない |
| --- | --- |
| 一人称の移動と視点（歩く・見回す） | 警官・店・就寝・保管庫・コツ |

| 宙の物を**掴んで鞄へ**。鞄の容量は有限 | 本番シーンへの変更 |
| 中身によって叩いた時の反応が違う | 2D の照明・像素の絵作り |

## 二、設計の芯

### 反応は「都市が話している」

叩いた時の揺れ方・音・弾み方が、中身を語る。**SAN＝都市を読む力**（`GameDesign.md` 第三節）が、手の感触になる。

- 中身は**叩く前に確定している**。`TrashCan` は次の 1 回分を先に引いて保持している（`_nextDraw`）。反応はその確定済みの中身から作る。
  再抽選しない。**反応は嘘をつかない**（第三節「情報を奪ってよいが、嘘をついてはならない」）。
- 試作では SAN は動かさない。本採用になったら、SAN が低いほど反応が鈍く・曖昧になる（`??` と同じ扱い。誤った手掛かりは出さない）。

### 「珍しい」の定義

本作のアイテムに希少度の項目は無い。**産出テーブルの重みから導く**（その表でその品が出る確率が低いほど珍しい）。
新しい数値を手で振らない。データにある事実から出す。

### 鞄の容量が、掴む判断になる

飛び出す物は、鞄に入る数より多くてよい。宙にある短い間に、**どれを掴むか**を決める。
格子式インベントリ（5c）が担うはずだった「何を持って何を捨てるか」を、手の操作と一瞬の判断で置き換えられるかを見る。

### 本採用後に繋ぐもの（試作ではやらない）

- **叩く音が注目度になる**。強く叩けば早く出るが、うるさい＝警官が来る（`ISuspiciousAct` の既存の経路）。
  毎回の漁りが小さなリスクとリターンになる。

## 三、技術の方針

- **新しいシーンを別に作る**（例：`Assets/Scenes/Proto_FirstPerson.unity`）。`FirstDistrict.unity` には触れない（`CLAUDE.md` シーンの所有権）。
- 本作の描画は URP の **2D Renderer**（`Assets/Settings/Renderer2D.asset`）で、3D の物体を正しく照らせない。
  **`UniversalRP.asset` の描画器一覧に Universal Renderer を一つ追加し、試作のカメラだけがそれを使う。**
  既定の描画器（index 0）は変えないので、本番シーンと 2D 照明には影響しない。最初の作業で、混在が実際に動くかを確かめる。
- 物理は 3D（`Rigidbody` / `Collider`）。本編のゲームプレイは 2D 物理なので、試作のコードは本編の型と混ぜない。
- **Core は再利用する**：`LootTable` / `LootDraw` / `FoodStateOdds`、`Assets/Config/TrashCanLoot.asset` と `ItemDatabase.asset`。
  中身の抽選と食品状態は本編と同じ規則で出る。試作のために Core を変えない。
- 入力は既存どおり Input System。
- 試作のコードは置き場所を分ける（Gameplay アセンブリの中の試作専用の名前空間、または試作専用のフォルダ）。本採用になれば作り直す前提で書き、本編から参照させない。
- プレイヤー向けの文字列はテキストモジュール経由（`CLAUDE.md` ローカライズの規約）。灰箱でも例外にしない。

### 段 1 の記録（2026-10-26）

- `Assets/Settings/Renderer3D_Proto.asset`（Universal Renderer）を作り、`UniversalRP.asset` の描画器一覧の index 1 に加えた。**既定は index 0 の 2D Renderer のまま。** 本番シーンの `Main Camera` は 2D Renderer で描かれていることを確認した。
- 試作シーン `Assets/Scenes/Proto_FirstPerson.unity`：カメラが `UniversalAdditionalCameraData.SetRenderer(1)` で 3D の描画器を使う。平行光源の照明と影が出ることを撮影で確認した。
- **落とし穴**：本作は 2D を既定にしているので、`CreatePrimitive` の既定の材質が `Mesh2D-Lit-Default`（2D 用）になり、3D の描画器では真っ白に出る。試作の物体には URP の `Lit` 材質を明示的に付ける（`Assets/Prototype/ProtoLit_*.mat`）。
### 段 1〜4 の実装（2026-10-26）

コードは `Assets/Scripts/Gameplay/Prototype/`（名前空間 `KyoumoMushoku.Gameplay.Prototype`）。本編からは参照しない。

| 部品 | 役 |
